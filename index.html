01 / THE FLOW

反馈流程

不用先判断是不是项目 Bug。把现象和资料描述清楚，剩下的交给开发者分析。

1

记录问题
记下发生了什么、在哪个阶段发生，以及怎样触发。

2

保存日志和系统信息
尤其是完整的 totk.log，不要只截取最后几行。

3

提交 GitHub Issue
搜索是否已有相同问题；没有的话新建 Issue，粘贴英文模板并附上日志。

02 / COLLECT THE CLUES

提交前，准备好这几项

这些信息能帮助开发者确认问题出现在哪个版本、哪类设备，以及能否在其他环境中复现。

版本信息 / Version

打开游戏设置菜单（F1），查看标题栏中的 TotK Recomp 版本和游戏更新版本。

系统信息 / System info

F1 → Advanced → Copy system info，把复制的完整内容粘贴到 Issue。

运行日志 / Log

在 totk.exe 所在目录找到 logs\totk.log。异常发生后先保存，再重新启动游戏。

复现步骤 / Reproduction

按顺序写下操作过程。比如进入哪个场景、打开哪个菜单、执行什么动作后出现问题。

如果游戏已经崩溃或卡住，先保留当次日志。不要为了“再试一次”而先启动多次，避免错过最有用的那份日志。
03 / READY TO SUBMIT

英文 Issue 模板

复制下面整段内容，粘贴到 GitHub 的 Bug Report 描述框，再按提示填写。

填写提示：不知道写 Unknown；不适用写 N/A。复现步骤尽量具体，日志请作为文件附件上传，不要只把日志内容截成图片。

04 / LOGS & ATTACHMENTS

日志和附件怎么准备

日志通常比一句“打不开”更有用。请尽量提供问题发生时的完整记录。

  • 打开游戏安装目录，也就是 totk.exe 所在文件夹。
  • 进入 logs 文件夹，找到 totk.log。
  • 如果问题发生后又启动过游戏，之前的日志可能已轮换为 totk.1.log 等文件。请附上对应问题发生时的日志。
  • 安装过程失败时，另外附上安装器日志：文件名以 install 开头的 `.log` 文件，以及 lift-gen.log。
  • 截图可用于展示报错窗口、黑屏、贴图异常或卡住的画面。

请上传原始日志文件。不要只贴最后几行，因为问题线索可能出现在更早的位置。

05 / BEFORE YOU POST

提交前检查

花半分钟检查一下，能减少来回追问，也能避免 Issue 因资料不足而难以处理。

  • 先搜索现有 Issues，确认没有相同问题。
  • 版本号、系统信息和复现步骤尽量填写完整。
  • 附上完整日志；如果有截图，也一并提供。
  • 不要上传游戏本体、固件、密钥、提取出的游戏资源或包含游戏内容的文件。
